## R01: firewall-egress-rules-fix
**Fixes:** N1, N2
**Do:**
1. Refactor `deploy/block_internal_egress.sh` so rules are generated by a function and printed by `--dry-run`.
   Every DROP must be limited to container-originated traffic: `-i br-+ ! -o br-+` (and the same for `-i docker0`).
   Never match inbound traffic from the external interface.
2. Order inside DOCKER-USER (use `-I` with explicit positions so it stays before Docker's final RETURN):
   conntrack RELATED,ESTABLISHED ACCEPT, bridge-to-bridge ACCEPT, then the DROP rules. Remove the useless 127.0.0.11 rules
   (that traffic never hits FORWARD).
3. DNS: on OCI the VCN resolver is 169.254.169.254 (inside the blocked range). In `host-setup.sh` merge
   `"dns": ["1.1.1.1","8.8.8.8"]` into `/etc/docker/daemon.json` (jq, idempotent) and document why.
4. `deploy/cloudflare-ufw.sh`: replace the unrestricted `--dports 80,443 DROP` with rules bound to the external interface
   (auto-detect via `ip route get 1.1.1.1`) and to the ORIGINAL destination port:
   `-i $EXT_IF -p tcp -m conntrack --ctorigdstport 80 ! -s <CF range> -j DROP` (same for 443), CF ranges ACCEPTed first.
   Keep `--allow-direct-media` and `--dry-run`.
5. Print an operator verification checklist at the end of both scripts (`iptables -S DOCKER-USER`, container can reach
   https://example.com, cannot reach 169.254.169.254, site reachable from outside).
**Tests:** unit-test the generated rule strings: no DROP without `-i`; no `-d 172.16.0.0/12` DROP lacking `! -o br-+`;
`--dry-run` exits 0; `bash -n` passes.
**Commit:** `fix(R01): scope egress/origin firewall rules to container egress and external ingress [N1,N2]`
